# CLAUDE.md

Team workspace for the **AIMO Interpretability Challenge (NeurIPS 2026)**, entered in the
**Small Models Track, open-weight category (<10B parameters)**.

- **Task:** implement `are_robust(model_id: str, problems: list[str]) -> list[bool]`. For
  each (model, problem) pair, predict whether the model's answer is **robust** (survives
  answer-preserving perturbations) or **spurious**.
- **Evaluation is per-problem since 15 Oct 2026:** `are_robust` gets a one-item list per call, 1 h 10 min
  budget, and the final test runs the same way (Finding 79). Batch rankings and counts no longer act.
- **What ships today:** `e64-difficulty` scored **0.71 (10/14)** per problem on 26 Oct, one case above the
  per-model constants (`e27f`, 0.64), and is the Form ZIP under its pre-registered rule (`submission/make_e64.py`).
  `e27k`'s 0.86 was the old batch protocol; per problem it collapses to the constants. Read `PLAN.md` §13 first:
  the final-push plan, E61/E63 (familiarity per problem, 8-9/14), E64 (difficulty) and E65 (E64 reverses on MATH).
- **This repository is the Small Models Track only.** The Main Track (adds `gpt-oss-120b`) lives in
  its own repository, `https://github.com/farhanishraq17/AIMO-Interpretability-Challenge-LARGE---Team-BakeNekos`;
  nothing here depends on it, the two only share the Kaggle accounts, and its `LF-n` findings are
  cited here by number only. **Paper content is written for this track only.**
- **Scoring:** Codabench competition 16180, not Kaggle. Kaggle is only free GPU capacity.
- **Deadlines:** submissions close **1 Nov 2026**; technical report and open-source code
  are due **15 Nov 2026**.

## Data and labels: invariants that must not drift

Recovered or measured facts that the pipeline depends on (evidence in `PROGRESS.md` §5–§7):

- **Label rule (our consolidated set, older tables):** `is_robust == (absolute_accuracy_decay <= 0)`. The organizers' rule is
  `== 0` (379/379 agreement). We use `<= 0` because 15 derived rows show improvement under
  perturbation; no published row is negative, so the two agree wherever testable.
- **Label rule (`train-main-v2`) is different and three-valued:** keyed on `max_drop`, not
  `absolute_accuracy_decay`. `true` iff `max_drop <= 0.10`, `false` iff `>= 0.25`, `null`
  between, with 0 violations over 82 rows. Band cases are unlabelled in validation and test
  too, so they are never scored. **The two labellings must never be aggregated for the same
  pair**: doing so corrupted two DeepSeek labels (Finding 44). `ingest_public.py` now lets the
  official split decide any pair it covers (`OFFICIAL_SPLIT_REPO`).
- **Eligibility:** `base_accuracy >= 1.0`; the task presumes the model solved the original.
- **Ambiguity band:** `(0.10, 0.25)` under the official rule; rows inside it carry no label.
  (`0 < decay <= 0.3` was the pre-20-Sep band, from the older recovered rule.)
- **Training set:** 226 train-ready instances (20 Sep). **153 are DeepSeek-8B (46 robust / 107
  spurious)**, of which 10 are officially labelled olympiad rows; 49 are Llama-3.1-8B, all
  spurious and useless as a classification target; Qwen3.5-4B 12, Olmo-3-Think 9 and Skywork 3
  come entirely from `train-main-v2`.
- **Grouped folds:** 5 folds in `data/small_track/splits.json`, grouped by `problem_key`
  (SHA-1 of whitespace-normalised text). 31 of the 156 train problems recur across models, so
  **never split ungrouped**.
- **`problem_key` is not sufficient for `train-main-v2`.** That table holds the same problem
  template with one constant swapped (`$10^{5}$` vs `$10^{4}$`, `f(3520)` vs `f(2024)`) under
  different labels: 36 distinct strings, 29 templates. SHA-1 of the text would split a template
  across folds and leak. Group by template there (Finding 34).
- **Model filtering is on by default.** `is_robust` belongs to a (model, problem) pair.
  `--no-filter-model` exists only for plumbing tests; its labels belong to another model.
- **Inference sees only `{model_id, problem}`.** No case id, no `permutation_type`, no
  `dataset_id`. Never train on a feature the harness cannot supply.
- **Metric discipline:** our split is 73.9% spurious, so always-spurious scores 0.739
  accuracy. **Track balanced accuracy and ROC-AUC during development.** Tune the decision
  threshold separately; the public val sample is 62.5% spurious and the private prior is
  unknown.
- **Floors to beat:** char tf-idf text model = **0.6732 balanced accuracy**. The shipped
  linear probe averages **0.5005** per layer (its 58.4% headline is a selection artifact).
  A method that cannot clear 0.6732 is reading surface form, not robustness.
- **Biggest known risk:** the private test set is entirely olympiad (AIMO/AIME/JMO) while our
  DeepSeek training rows are almost all Hendrycks MATH. `train-main-v2` is the first official
  olympiad-labelled material (36 problems, 2025 AIME I among them), and every block measured
  against it is at or below chance (Findings 32, 39, 40).
- **All four small-track models now have some public labels**, via `aimo-interp/train-main-v2`:
  Qwen 12, Skywork 3, Olmo-3-Think 9, DeepSeek 10 (34 rows, 71% robust). Enough to check a
  constant or estimate a prior, **not** to train a per-model model. E11 v2 answers `True` for
  Qwen and `False` for the other two (Findings 21, 27), which disagrees with the official rows
  labelling Skywork 2/3 and Olmo 7/9 robust — too few rows to flip on (Finding 33).
  Self-labelling (E15–E19) is **closed**: `answer_modulus` does not measure official robustness
  (Finding 31). `Olmo-3-7B-Instruct`, used in E3, was a warm-up model and is not evaluated.
- `aimo-interp/problems-public` (symbolic chains) returns 401 and is unavailable (re-checked
  19 Sep 2026).

## Competition contract (submission code)

- `solution.py` at the ZIP root, exposing `are_robust`. Return **native Python `bool`s**,
  one per problem, same order; NumPy bools or ints are invalid predictions.
- Small-track ZIPs need a root-level `small.txt`; main-track ZIPs must not contain one.
- Offline evaluation: `HF_HUB_OFFLINE=1`; load with `local_files_only=True`; no pip, no
  network. Allowed imports are the stdlib plus the `Dockerfile.competition` pins.
- **Small-track models** (Competition Phase, passed verbatim, no aliases):
  `Qwen/Qwen3.5-4B`, `Skywork/Skywork-OR1-Math-7B`, `allenai/Olmo-3-7B-Think`,
  `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`. All four have some public labels via
  `train-main-v2`; only DeepSeek has enough to train on. Main Track adds
  `openai/gpt-oss-120b`. Return `[False] * len(problems)` for models you do not cover rather
  than raising.
- Budget: **3600 s** for the whole prediction run on **one** RTX PRO 6000 (96 GB, Blackwell,
  bf16). A cached 4–8B model loads in about 2 s. Ties break on runtime.
- Accept both call styles: `are_robust(model_id, problems)` and
  `are_robust(model_id, reasoning_effort=..., problems=...)`, which is **merged upstream** as of
  `de79405`, not pending. The E11 signature `(model_id, problems, reasoning_effort="default")`
  works under both. Small-track cases are always `"default"`; `train-main-v2` also carries
  `"high"`, so do not assume the README's three values are exhaustive.
- **Load the DeepSeek tokenizer as `PreTrainedTokenizerFast`**; `AutoTokenizer` strips
  whitespace under transformers 5.13 (Finding 14). Use `datagen/tokenizer_check.py`.
- **Fit every shipped sklearn/joblib artifact in the pinned local venv**, never on Kaggle.
  Load-test the ZIP in `Dockerfile.competition` before uploading.
- Never bundle datasets, labels, model weights, venvs, `__pycache__`, or credentials.
- **Extra-data rule:** no extra *labelled* data for the official perturbation types
  (`rephrase`, `rename`, `domain`, `distract`, `typos`, `expert_perturbations`,
  `expert_no_solution`). Unlabelled data and labels for other perturbation types are allowed.
  Document every generated dataset for the report.

**How experiments run.** `datagen/kaggle_launch.py` holds the `EXPERIMENTS` registry

1. pip-installs the runtime pins, leaving Kaggle's torch alone;
2. unpacks the bundle to `/tmp/aimo-repo`;
3. runs each step with `HF_HOME=/tmp/hf`, streaming logs to `/kaggle/working/logs/`;
4. writes `run_manifest.json`.

and its run manifests to `kernels/`, so an experiment can be rebuilt from this repository even
if the Kaggle account disappears.

holds every alias's token or every downloaded run. The script falls back to the committed kernel
slug and `downloaded_run` rather than overwriting them, but `bundle_files` still shrinks to the
files present locally and `bundle_sha1` shifts because some bundles embed git-ignored data. After
an export, **commit only the kernels you actually changed** and `git checkout --` the rest.

To add an experiment, add a registry entry and push; don't edit kernels on Kaggle. If a new
step needs another repo file, add it to `BUNDLE_FILES`. Kernels are private
(`is_private: true`); keep them that way.

**Kaggle gotchas (all hit or verified):**

- Use `machine_shape: NvidiaTeslaT4` (2x T4, 15 GB each). An 8B model in fp16 needs
  ~16.4 GB, which does not fit on one P100.
- **dtype on T4 is bf16 in practice.** The T4 (Turing) has no native bf16 kernels, but
  Kaggle's torch (2.10.0+cu128) reports `torch.cuda.is_bf16_supported() == True` through
  emulation. `--dtype auto` and the starter kit's loader therefore pick bf16, the same dtype
  as evaluation. E1 and E3 ran that way at about 1.0 s per instance with zero non-finite
  activations. The guards stay in case a host falls back to fp16, where Qwen-family models
  can overflow:
  - Stage A records `n_nonfinite_activations`.
  - Stage B aborts if the preflight logits are non-finite.
  - Both record the dtype in `metadata.json`; check it before trusting features.
- `device_map="auto"` places layers on different GPUs, so tensors used for indexing must
  follow each layer's device (the bug fixed in `pool_hidden_states`).
- Keep model weights out of `/kaggle/working`: it is capped at 20 GB and saved as output.
- `kaggle kernels output` downloads **one page** per call (max 200 files). Merge on Kaggle and
  skip per-instance vectors; the launcher already does both.
- `kaggle quota` crashes in CLI 2.2.2 ("not enough values to unpack"), and so does the SDK call under it.
  `python scripts/kaggle_quota.py` reads the same endpoint directly: used, running and remaining GPU
  hours for every alias, and when the weekly window resets (Saturday 00:00 UTC).
- `kaggle datasets list` has no `--page-size`; `kernels list --mine` does.

## Code conventions

- Module docstring first, explaining **why** the script exists and what it deliberately does
  differently, then a `Run:` line. Match that style and comment density.
- `argparse` with explicit defaults; `pathlib` paths anchored at `ROOT`; `pyarrow`/`pandas`
  parquet I/O; `from __future__ import annotations`.
- GPU jobs must be **shardable** (`--num-shards/--shard-index`, round-robin over hash-sorted
  keys) and **resumable**: flush one record per instance or batch, and skip completed keys on
  restart.
- Record provenance next to every output (`metadata.json`: model, dtype, GPUs, library
  versions, prompt SHA-1, generation config), and make mergers refuse inconsistent inputs.
- Reuse starter-kit code rather than re-implementing it (for example, Stage B imports
  `uncertainty_profile` unchanged), so features match what runs at evaluation time.
- Prompts for representation work must match the probe baseline exactly: the system prompt
  from `probe_artifact.pkl` (SHA-1 `9021e9d4…`) and the chat template with
  `add_generation_prompt=True`. Never transcribe the prompt by hand.
- Generated outputs (`data/`, `features/`, `runs/`, `kaggle_runs/`, `dist/`) are git-ignored
  and must regenerate deterministically.
- Treat `getting-started/` as vendored upstream code: extend it from our own directories
  instead of editing it, so upstream updates can be pulled.
